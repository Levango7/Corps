# ADR-013: 旧聊天实现树（ChatPanel + components/chat/*）登记为"待整合的未挂载实现"

> 状态：已采纳 → **已整合完成（2026-10-27，见文末「执行记录」）**
> 日期：2026-10-06
> 关联：ADR-009（IM 轻沟通 MVP 启动）、ADR-012（文档协同降级）、
> `web/components/ChatPanel.tsx`、`web/components/chat/*`、`docs/audit/REVERIFY-2026-09-29.md` 第 12 行

## 背景

仓库里存在**两套**聊天 UI 实现：

| 树 | 入口 | 当前状态 |
|---|---|---|
| 新（在用） | `components/im/IMClient.tsx`、`components/im/TaskChatPanel.tsx` | 挂在 `/w/{wid}/im` 与 `/w/{wid}/task/{id}` |
| 旧（本 ADR 主题） | `components/ChatPanel.tsx` + `components/chat/*` | **零挂载** |

2026-10-06 实测的可复现判据（不是引用谁的结论）：

- `grep -rn "ChatPanel" web/app --include="*.tsx"` 只命中 `TaskChatPanel`（不同组件）与
  `AiChatPanel`（也不同）——**没有任何页面 import `components/ChatPanel.tsx`**。
- `components/chat/*` 的唯一外部引用方就是 `ChatPanel.tsx` 自己
  （`ChatPanel.tsx:7-11` 引 `./chat/types`、`useChatStream`、`ChatHeader`、`MessageList`、`MessageInput`），
  所以它随 ChatPanel 一起不可达。
- 规模：**7 个文件 / 2,101 行**（含 `chat/useChatStream.ts` 263 行的 SSE 流实现）。
- 另一处容易误判的点已排除：文档侧 AI 面板 `components/editor/AiChatPanel.tsx:4-5` 用的是
  `@ai-sdk/react` 的 `useChat` + `ai` 的 `DefaultChatTransport`，**没有复用** `chat/useChatStream`，
  所以"其实它还在跑"这个假设不成立。

因此台账第 12 行"写了没人读"这条仍然有效，但描述要纠正：不是"没人引用"，
而是**被一个没有挂载点的父组件引用**。

## 决策

**保留代码，不删**；但按三件事收口，让它不再污染对外叙述与后续判断：

1. 在 `ChatPanel.tsx` 顶部写明"未挂载的旧实现，勿在新页面直接引用"，并指向本 ADR。
2. 对外能力叙述里**聊天只有一套**：团队协作 = IM（`components/im/*`），AI 助手 =
   `AiChatPanel`。任何文档/README 不得把 `components/chat/*` 计为额外能力。
3. 未来的整合路径是显式的：要么把 `chat/*` 里确有价值的部分（如 `MessageInput` 的
   memo 隔离、`ChatHeader` 的拆分）逐文件迁进 `components/im/*` 并让 IM 复用，
   要么在完成迁移后整棵删除。**不允许**新页面直接 import `ChatPanel`——那会把
   两套实现同时在生产里点亮。

## 为什么不按"确定没用就清理"删掉

用户的既有裁决是**功能上不做减法，做整合**（`ROADMAP-2026Q4.md` §3）。而这棵树并不满足仓库
自己的"确定没用"判定标准（`ADR-012` 同款口径：代码零引用**且**无部署链路）——它有完整的
SSE 流实现与已翻译的 i18n 文案，属于"待整合"而非"待删"。删掉 2,101 行换来的是
把一次尚未做的技术选型（IM 树要不要吸收它的输入框/头部设计）提前决定，收益是零。

## 代价与监控

- 代价：这 7 个文件仍在 `web/` 的 tsconfig 与 eslint 覆盖内（`web/tsconfig.json` include 以
  `web/` 为根），所以**不会脱离门禁**，只是持续无测试覆盖——它们全部在
  `scripts/zero-coverage-baseline.txt` 的零覆盖名单里。这条基线"只允许收缩"，
  因此如果将来真把它们接上，棘轮会要求同步删除对应行（与 2026-10-05/06 两次
  `STALE_COVERED` 一样是预期内的红）。
- 监控：不新增专门门禁。理由是给"未挂载组件"建一道静态守卫，要么按目录猜（易误判），
  要么维护一份豁免清单（多一份会腐坏的账），收益不及 ADR + 代码注释 + 零覆盖基线三者叠加。

## 执行记录：整合完成（2026-10-27）

状态由「保留待整合」改为**已整合**。做法与判据如下，结论以本节为准。

### 1. 先量后删：旧树不只是"没挂载"，它自己的链路已经坏了

逐文件比对两棵树（旧 8 文件 / 2,109 行 vs `components/im/*` 6,095 行）后，实测到三处：

- `GET .../tasks/{id}/messages` 只 include `author`（`messages/route.ts:50-66`），
  而旧树 `chat/types.ts:38-39` 依赖 `reads` / `attachments`
  ⇒ 历史消息的未读数恒错、回执恒 0、历史附件永不渲染（实时 SSE/发送路径才有这些关系）。
- `ChatPanel.tsx:178-191` 一次把**全部**未读 id 交给 `read`，端点上限 100（`read/route.ts:27`）
  ⇒ 超限 400 后 ids 被还原，形成 1 秒重试循环。
- 服务端搜索分支（`chat/MessageList.tsx:136-164`）因 `ChatPanel.tsx:306-313` 从不传 `searchUrl`
  而永远不执行；`members`（@提及）与 `uploadUrl` 同样从未传入。

⇒ "留着等将来接线"不成立：要接就得先修完上面三条。

### 2. 把确有价值的机制搬进 IM（"整合"的实质）

- **操作失败就地提示**：`chat/MessageBubble.tsx:345` 的 `role="alert"` 迁到
  `im/MessageItem.tsx`（失败时保持编辑态、内容不丢，可直接重试）。
  这条不是美化，是补真缺陷——实测 IM 的失败路径**完全静默**：
  `useIM.editMessage/revokeMessage` 会 `setError` 并 **rethrow**，但
  `IMClient.tsx:215-218` 用 `.catch(() => {})` 吞掉、`TaskChatPanel.tsx:119-120` 用 `void` 丢弃，
  而 `IMClient.tsx:265` 只在"未选中会话"时渲染 `error` ⇒ 会话内编辑/撤回失败，
  用户看不到任何提示；任务面板那条还会成为未处理拒绝。
  配套修类型：`onEdit`/`onRevoke` 的 prop 类型由 `=> void` 改为 `=> void | Promise<void>`
  （旧类型让 `await` 立刻拿到 `undefined`，错误照样被吞）。
- 判为近似重复、随文件删除的：滚动定位与回到底部、今天/昨天标签、气泡/头像/附件/
  30 分钟撤回窗口/已读回执、@提及 listbox、上传与拖拽、头部标题 + 搜索开关。

### 3. 未迁移（如实记账，不是"已经等价"）

- `chat/MessageInput` 的 **memo + 非受控输入**隔离：IM 的输入框受控且未 memo，
  每次轮询/消息推送重渲染会重建（当前状态本身安全，属性能优化项，未做）。
- 5 分钟分级时间戳：IM 按自然日分组 + 每条相对时间，信息量不减，故不迁。
- 正文内 `<mark>` 搜索命中高亮：未迁。
- 在线成员头像条：旧树里本就是半接线状态（数据从未传入），不迁。

### 4. 删除与基线同步（同一提交）

- `git rm` 8 文件：`components/ChatPanel.tsx` + `components/chat/{ChatHeader,ChatHeaderClient,MessageBubble,MessageInput,MessageList}.tsx`
  + `components/chat/{types,useChatStream}.ts`。
- `scripts/zero-coverage-baseline.txt` 删 6 行（ChatPanel + 5 个 `.tsx`）。
  `chat/types.ts`、`chat/useChatStream.ts` 是 `.ts`，不在 `coverage.include` 范围内，本就不在基线。
- `web/tests/a11y-baseline.txt` 删 4 行（原有 1+1+2+1=5 条违规），
  并把头部三个数字按现测改为 **794 文件 / 98 个带违规 / 228 条**（行数 172）。
- 本地实跑：`a11y-baseline` + `zero-coverage-baseline` 一致性单测 **10 passed**；
  `tsc --noEmit` 退出 0；`scripts/check_adr015_manifest.py` 21/21 一致退出 0。
