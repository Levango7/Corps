# ADR-003: 计费方案

## Status

Accepted (2026-08-19) — MVP 路径（Stripe Checkout / Portal / webhook）已锁定。
OPEN 子项：国内支付选型（Stripe 跨境 vs 微信支付 / 支付宝）待定，见文末 OPEN 项与倾向结论。

## Background

计费为 P1 功能（Spec 第 2 节），需满足：席位计费雏形（Stripe Checkout + Portal + webhook）、成员数变更同步 subscription quantity（AC-08）、扣款失败触发催缴不立即中断服务（AC-09）。目标市场为中国大陆（Spec 第 1、10 节）。候选：

- **A. 仅 Stripe（跨境）**：Checkout/Portal/webhook 成熟，集成快；但 Stripe 在中国大陆需跨境收单，存在合规与外汇结算不确定性，国内持卡/扫码体验不如本地钱包。
- **B. 仅微信支付 / 支付宝**：国内直连体验与合规最稳，但订阅（按席位按月续费 + 数量变更）需自行实现账单与催缴，工作量高于 Stripe 订阅。
- **C. Stripe 跑通 MVP 订阅逻辑 + 抽象 `PaymentProvider` 接口，生产环境可切换微信/支付宝**：兼顾速度与可替换性。

## Decision

MVP 采用 **Stripe 作为默认计费实现**（方案 A 的集成方式 + 方案 C 的抽象）：

- 升级：POST `/api/v1/billing/checkout`（Owner 专属）创建 Stripe Checkout Session，`quantity` = 当前 workspace 活跃席位数。
- 自助管理：Stripe Customer Portal 处理升降级/付款方式（不另建账单 UI）。
- 回写：POST `/api/v1/billing/webhook` 用 `Stripe-Signature` 验签后处理 `checkout.session.completed`、`customer.subscription.updated`（同步 `subscriptions.quantity`，AC-08）、`invoice.payment_failed`（置 `past_due` 并触发催缴，AC-09，不立即中断服务）。
- `subscriptions` 表存 `stripe_customer_id` / `stripe_subscription_id` / `quantity` / `status`（schema 见 `db/schema.sql`）。
- 抽象：计费逻辑经 `PaymentProvider` 接口封装（createCheckout / syncSubscription / handleWebhook），使支付通道可替换，不为 Stripe 硬编码业务规则。

## Consequences

正面：

- 用最少的集成成本跑通完整订阅生命周期（含席位数量同步与催缴），满足 P1 验收。
- `PaymentProvider` 抽象使后续接微信/支付宝时无需改业务层。
- Stripe webhook 的 quantity 同步天然覆盖 AC-08，payment_failed 状态机覆盖 AC-09。

负面 / 代价：

- Stripe 跨境在中国大陆的合规/结算风险未消除（即 OPEN 项）；若监管或收单受阻，需切换到本地钱包。
- 抽象层在 MVP 仅一个实现，存在"为未来过度设计"的轻微代价，但换取可回退性，划算。
- 微信/支付宝的订阅与按席位续费需自行实现账单与催缴，工作量高于 Stripe 订阅，留待生产切换时投入。

## OPEN 项与倾向结论

Spec 第 13 节 OPEN-DECISIONS 登记：国内支付选型（Stripe 跨境 vs 微信/支付宝），当前倾向"优先 Stripe 跨境验证，不行则微信/支付宝"，状态 OPEN。

**架构师倾向结论（本 ADR 给出）**：

1. MVP 阶段以 Stripe（test mode 起步、生产走跨境收单）验证完整订阅与席位同步逻辑，不要在 MVP 同时建两套支付集成——避免范围爆炸（契合 Spec "砍范围"原则）。
2. 生产环境（中国大陆上线）**首选微信支付 / 支付宝**作为主支付通道：本地钱包合规最稳、国内直连体验与转化率更好；Stripe 降级为跨境 / 海外客户备选。理由：目标市场明确为中国大陆（Spec 第 1、10 节），而 Stripe 中国大陆跨境收单受外汇与合规约束，作为唯一生产通道风险偏高。
3. 落地要求：`PaymentProvider` 抽象在 MVP 即落地（不为 Stripe 写死），并为微信/支付宝实现预留 `createCheckout`/`syncSubscription`/`handleWebhook` 契约，使"不行则切换"可在不改动业务层的前提下完成。
4. 待用户最终确认价目表（Spec OPEN：¥59/人/月 起步档）后，再冻结 `stripe_price_id` 与本地钱包费率配置。

状态：MVP Stripe 路径 Accepted；国内支付最终选型保持 OPEN，按上述倾向推进。
