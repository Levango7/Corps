# ADR-015：未接线的云盘 / 预览组件登记为"待接线"，不得当作死代码删除

- 状态：**待决策（已登记，暂不删除）**
  - **2026-10-09 补充：§5 的约束已从"文档"升级为"CI 门禁"**——登记表
    `scripts/adr015-manifest.txt` + 校验脚本 `scripts/check_adr015_manifest.py`，
    挂在 CI 的 `lint` job（`lint` 已是 required status check，无需改分支保护）。
    删掉这 20 个文件里的任何一个，现在会**直接把 CI 打红**，
    不再依赖"下一个动手的人记得先读过这份 ADR"。
  - 仍未决的是**选型**（§4 的 A/B/C 走哪条），而不是"能不能删"。
- 日期：2026-10-08
- 触发：审计遗留项里有一条"`FilePreview.tsx` / `previews/ImagePreview.tsx` 死代码 + `_fileType?` 僵尸字段"，
  实际核实后发现范围与性质都与原记录不符，故单独登记，避免下一个 agent 以"清理死代码"为名动手。

## 1. 结论先行

`web/components/files/**` 与 `web/components/im/FilePreview.tsx` 共 **20 个文件、2007 行**，
在当前代码里**静态零引用**：

- 没有任何 `app/**` 页面路由 import 它们（`find app -type d -name files` 只命中
  `app/api/v1/workspaces/[wid]/files`，那是 **API 路由**，不是页面）。
- `components/files/previews/` 整个目录（7 个文件）在 `app/ components/ lib/ e2e/ tests/` 下
  **一次都没被 import**（`grep -rn "previews/"` 零命中）。
- `FilePreviewDialog` / `FileBrowser` / `FileVersionRestore` / `FileVersionList` 也只有注释里
  互相提到，没有真正的 import 方。

**但这不是"腐烂的死代码"，而是"后端已上线、UI 没挂载"的半成品。** 判据是：

- 后端 API 是活的：`app/api/v1/workspaces/[wid]/files/**`（含 `route.ts`、`[fid]/route.ts`、
  `[fid]/move`、`[fid]/versions`、`[fid]/download`、`upload`）都在，且被 `FileAsset` 模型支撑。
- 这 20 个文件恰好是那套 API 的**前端**：`FileBrowser`（列表/网格 + 上传）、
  `FileUploader`（328 行，最完整的那个）、`FileVersionList` / `FileVersionRestore`（版本管理）、
  `previews/*`（7 种预览器）。
- 也就是说，缺的只是"一个页面把这些组件挂上去"这一步。删掉它们 = 把一个后端已完成的
  功能砍掉一半。

## 2. 两套并行的预览实现（这才是真正的技术债）

同一个功能有两份互不相干的实现，且**都不在链路上**：

| 实现 | 文件 | 谁引用它 |
|---|---|---|
| 统一入口 + 兄弟组件 | `components/files/FilePreview.tsx`(238) + `PdfPreview`(28) + `VideoPreview`(25) + `TextPreview`(128) | 仅被 `FilePreviewDialog.tsx` import，而后者零引用 |
| 独立预览器目录 | `components/files/previews/{Audio,Code,Image,Markdown,Office,Pdf,Video}Preview.tsx`(共 267 行) | **零引用** |

`FilePreview.tsx` 的文件头注释写着"根据文件类型分发到 PdfPreview / OfficePreview / ImagePreview…"，
但它实际 import 的是**同目录的兄弟**（`./PdfPreview` 等），并且**自己在文件内重新定义了一个
`ImagePreview`**（:89），而不是用 `previews/ImagePreview.tsx`。所以：

- 注释描述的分发关系与代码不一致；
- `previews/` 那 7 个（含 `CodePreview` / `MarkdownPreview` / `OfficePreview`，能力比兄弟版更全）
  是被"另一条路线"取代后被遗弃的；
- 接线时必须**先决定用哪一套**，否则会接上一套、留另一套继续烂。

## 3. 附带的小缺陷（低风险，但值得单独记）

`components/files/FilePreview.tsx:40` 有一个僵尸字段：

```ts
  /** ESLint unused-args 兼容：内部别名 */
  _fileType?: string;
```

注释本身说明它是为了绕过 lint 而加的假字段，而 `fileType`（:38）才是真字段，`_fileType`
在 :163 被解构后从未使用。这是"用加字段的方式消 lint 报错"的典型痕迹——
正确做法是删掉它并让 lint 报出来。因为它长在待决策的文件里，本次不动，登记在此。

## 4. 处置选项

| 选项 | 动作 | 评价 |
|---|---|---|
| A（推荐） | **接线**：加一个 `app/[locale]/w/[wid]/files/page.tsx`，先把 `FileBrowser` + `FileUploader` 挂上，预览器二选一并弃用另一套 | 后端已就绪，这是唯一能让 2007 行产生价值的路径；顺带把两套预览收敛成一套 |
| B | **登记归档** —— ~~在文件头加 `@deprecated 待接线，见 ADR-015`，并加一条 shrink-only 的引用计数基线防止继续腐化~~ **已实施（有变形，2026-10-09）**：**不往那 20 个源文件里注入注释**（同一份信息集中写在登记表抬头即可，无谓地改 20 个文件反而会和并行会话的改动打架），改为登记表 `scripts/adr015-manifest.txt` + 门禁 `scripts/check_adr015_manifest.py` | 债继续挂着，但**已无法被静默删除**；详见 §5 |
| C | **删除** | **不推荐**：等于砍掉一个后端已完成功能的前端，且 `previews/` 里

## 5. 给后续 agent 的硬约束

> 在 ADR-015 状态从"待决策"变为"已接线"或"已删除"之前，
> **任何会话都不得以"清理死代码"为由删除 `web/components/files/**` 或
> `web/components/im/FilePreview.tsx` 下的任何文件。**
>
> 若你确实要推动这一项，请先把本 ADR 的状态改成"已接线/已删除"并写明理由与验证方式
> （删除必须在同一提交里更新本 ADR，且跑通 `tsc` + `eslint` + 单测 + `next build`）。

### 5.1 这条约束现在是机器判据，不再是"请记得"

原先它只是这份文档里的一段话——**文档拦不住下一个以"清理死代码"为名动手的会话**，
因为约束只活在"对方恰好读过这份 ADR"这个假设上。现在它由 CI 强制：

```bash
python scripts/check_adr015_manifest.py              # 常规校验
python scripts/check_adr015_manifest.py --self-test   # 注入变异自检（8 个用例）
```

三种红因，各自独立：

| 红因 | 含义 |
|---|---|
| `ADR015_FILE_MISSING` | 登记表里的文件不见了（= §5 禁止的那个动作） |
| `ADR015_UNREGISTERED` | 扫描范围内出现了登记表之外的文件（新增/搬家却未登记） |
| `ADR015_MANIFEST_DIRTY` | 登记表自己有条目重复（表已不是可信清单） |

**解除约束的正规路径（唯一）**：改本 ADR 状态 + **同一提交**更新登记表。
只改登记表、不改 ADR，视为绕过约束。

### 5.2 这条门禁的诚实边界

登记表本身是普通文本，所以「删文件 **+ 顺手删掉表里那一行**」**能**绕过它
（实测：该组合红因为空）。这与仓库里既有的棘轮闸门（如
`scripts/check_v1_guard_ratchet.py` 的基线文件）是同一信任级别，不高也不低。

它真正的价值不是"物理上禁止"，而是把**默认动作从绿灯变成红灯**：一次 `git rm`
会立刻在 CI 上留下痕迹，于是删除必须变成一个**显式的、要写理由、会被 review 的动作**，
而不是顺手为之。剩下那半步靠人看 diff。

```bash
# 4. 若变成非零引用，说明已接线，应更新本 ADR 状态
```
