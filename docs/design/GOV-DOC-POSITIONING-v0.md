  公文强相关词频 3/17（行 74），品目级全文级证据 3 份：#4 粤政易（2051.68 万，含
  「OFD 版式文档预览软件**租赁**」品目，行 26）、#17 恩施（公文管理+交换系统+短信提醒，行 39）、
  #6 西安（市级公文传输系统运维，行 28）；国企口 S-1 同构（行 111）。
- §11 长短期对比结论：短期续约杠杆在 P2 数据迁移，长期壁垒在 P1（OFD 版式 + 公文交换），
  推荐 P1 立即立项，理由「工期最长不能等」（行 146）。

**Repo 侧现役事实**（本文件所有能力陈述的取数处）：

- **OFD/版式代码为零**：全仓 `web/ api/ db/` grep `ofd` 零命中（仅有的 3 处命中是
  `startOfDay` 子串误伤，已逐行核）；
- 通知模块现役（`web/app/api/v1/workspaces/[wid]/announcements/route.ts`），但**短信触达通道为零**
  （sms/短信 全仓零命中）；
- 生产 RLS **未通电**：#51 pending（Vercel 实例以 owner/bypassrls 连接），G1a 收口在 #75 lane；

## 2. 定位声明

> **公文模块＝面向政府/国企垂直市场的品类入场券**：收文、办理、发文、交换对接、
> OFD 版式呈现五件事的最小闭环，让 Corps 在协同办公标里**不被品目表淘汰**，
> 并把办理结论回填到现役「决策落位」楔子（公文办理结论 → 任务/决策记录）。

两个明确：

- 它**不改变主定位**（POSITIONING.md：中小团队轻量协作 + 决策落位楔子）；
- 它**不是**「政务版飞书」——政务微信集成（P4）、移动办公端（P3）、数据迁移（P2）、
  预算费控（survey §11 排除项）均不在本模块。

## 3. 边界（是什么 / 不是什么）

| 子项 | v0 范围 | 依据 |
|------|---------|------|
| 公文管理（拟稿/核稿/签发/归档轻量流） | 自建，复用审批引擎 + 模板编辑器 | 审批现役（§1）；#17 品目原文即「公文管理」 |
| 公文交换（跨单位对接层） | 只做**对接层**（接口适配+状态回执），通道本身合作/外购评估 | repo 零现役；交换通道涉跨单位标准与运营，自建不现实 |
| OFD 版式呈现（阅读/批注/打印） | 外购/租赁评估优先 | #4 品目原文即「OFD 版式文档预览软件**租赁**」；repo 零现役 |
| 归档 | 并入公文管理流，不单独立项 | 与 P2 迁移工具共享落盘能力（长期） |
| 短信提醒 | **不立项**（排除项） | survey §11：只做通道核查；且 repo 短信通道=0 |

## 4. 与 POSITIONING.md §5 冻结令的关系（正面处理）

§5「试点证明决策闭环被使用之前，冻结横向补功能」。公文模块**不是该令的第三条反模式**
（「飞书有 X 我们也要有」），判据：

1. 它服务的是**品类入场券**（没有它政府/国企品目直接出局，survey §7「缺口最大单点」），
   不是功能广度对齐——POSITIONING.md §2 自己写明「功能广度只是入场券」；
2. 它不进首屏：默认进「更多」模块（对齐 L2，注册表约定 + `module-registry.test.ts`），
   上行首屏要试点/垂直客户数据；
3. 它与楔子有结构接口：办理结论落位成任务/决策，是「讨论→决策→任务」闭环在
   政务语境的实例化，不是又一块拼盘。

结论：**立项做 v0 定位与原型，不进主迭代首屏、不占 #46 试点资源**。
若业主判它仍属「横向补功能」，则本定位作废，回冻结令。

## 5. 三问评审（POSITIONING.md §6）

| 问 | 答 |
|----|----|
| 首次价值时间变短还是变长？ | 垂直 lane：政府/国企新用户无公文则 L3 不可测（入场前提）；主产品用户不受影响（默认收起） |

| 服务楔子还是「别人有」？ | 品类入场券 + 与楔子有结构接口（办理结论→决策落位） |

## 6. 与既有 lane 的排序

- 与 #46 试点：不互斥（试点测楔子闭环；公文 v0 原型独立资源）；
- 与 P2 数据迁移：survey §11 推荐 P2 并行（短工期抢续约杠杆），本定位不改动该序；
- 与 G1 安全合规包：公文模块对外文案的隔离能力陈述，以 G1a 生产通电（#75，姿态脚本 GREEN）为前置——
  **未通电前投标文案不得写「租户数据引擎层隔离」**（C 口径）。
