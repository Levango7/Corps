# 产品定位：轻量办公协作平台（2026-10-23 用户确认）

**状态**：用户 2026-10-23 明确口径——早期定位「面向中小团队的轻量协作平台」**不是过时说法**，
它与「办公系统」不冲突，因为两者回答的不是同一个问题。本文把这两句话固定成**两个轴**，
并给出可测口径，避免后续排期把「轻量」稀释成一句文案。

---

## 1. 一句话

> **面向中小团队的轻量办公协作平台 —— 把会后的讨论落成决策与任务。**

- **品类词**：办公协作（这是"什么"）
- **形容词**：轻量（这是"凭什么换"）
- **楔子**：决策落位（这是"为什么不是又一个飞书"）

## 2. 两个轴，不是二选一

| 轴 | 内容 | 回答谁的问题 | 反面 |
| --- | --- | --- | --- |
| **品类** | 办公系统：文档 / 任务 / 决策 / 消息 / 日历 / 知识库 | 采购者、新用户："这是什么？" | 只做单一工具（如纯看板），装不下办公场景 |
| **楔子** | 面向中小团队的**轻量**协作：开通即用、无组织改造、首屏不塞 30 个入口 | 使用者："凭什么从钉钉/飞书换过来？" | 做成"小号飞书"：拼功能广度，必输 |
| **差异化** | 讨论 → 决策 → 任务 的闭环 | 决策者："它解决了我哪件具体事？" | 又一个任务板 + 聊天的拼盘 |

**关键判断**：我们与钉钉/飞书的竞争**不在功能数量**，而在两件事——
1. **零配置开通**：不需要 IT 建组织架构、不需要管理员统一推行；
2. **会后落位**：把"会开完了"变成"有决议、有责任人、有截止时间"，且能追溯。

功能广度对我们**只是入场券**（用户会问"有没有文档/日历"），不是胜负手。

## 3. 把「轻量」变成可测口径

形容词没有判据就会漂。以下四条是「轻量」的**操作定义**，新功能评审时逐条对照：

| # | 口径 | 当前状态 | 守它的东西 |
| --- | --- | --- | --- |
| L1 | 首屏入口 ≤ 10 | ✅ 核心 6 + 管理 4 | `DEFAULT_VISIBLE_MODULE_IDS` + `module-registry.test.ts` |
| L2 | 新模块**默认进「更多」**，想上首屏必须有数据支撑 | ✅ 21 个可选模块默认收起 | 注册表约定 + 同一条单测（并集恒为 31） |
| L3 | 注册 → 第一个任务 ≤ 15 分钟 | ⏳ 未测（对应 H1 / 场景 A） | 待试点埋点（`activation_completed`） |
| L4 | 完成「会后备忘 → 决策 → 任务」必填配置项 = 0 | ✅ 不需建部门/配权限/导成员 | 现有注册流（邮箱 + 工作区名） |

L1/L2 已经是代码级门禁；L3 是试点期的度量目标；L4 是设计约束（任何"先配置才能用"的引导都违反它）。

## 4. 三条反模式（出现即视为定位漂移）

1. **强制引导**：注册后必须走完 N 步向导才能用（违反 L4）。
2. **管理员强推**：产品价值依赖"管理员统一开通/强制全员使用"（这是钉钉/飞书的赢法，不是我们的）。
3. **功能对齐式排期**："飞书有 X，我们也要有 X"——广度永远追不上，且会挤掉楔子的验证时间。

## 5. 排期规则

**在试点证明「决策闭环」真的被使用之前，冻结横向补功能。** 只做三类：

1. **降低首次价值时间**（L3/L4：注册流、空状态引导、示例工作区）；
2. **把决策闭环做深**（落位、责任人、截止、复盘、可度量）；
3. **修信任底线**（RLS/租户隔离、备份恢复、监控、登录找回）。

审批、OKR、工时、多维表等**保留但不投入新开发**——它们已在「更多」里，不影响轻量体验。

## 6. 评审用法（新功能三问）

- 它让**首次价值时间**变短还是变长？
- 它让**首屏/必填配置**变多还是变少？
- 它服务的是**楔子**（决策落位），还是只是"别人有"？

三问里有两问答不上来，就不该进当前迭代。
