**陷阱记录（会直接把"绿的集成"变成假红）**：Windows 上 Docker Desktop 的
`com.docker.backend.exe` 会占住某些端口的 **IPv4 环回位**（实测 3100）。
Node `fetch("http://localhost:3100")` 解析到 `127.0.0.1` → 打到 Docker 的监听器，
返回 Go 风格 `404 page not found`；`curl` 走 `::1` → 打到 Next。
症状是"路由 404、注册失败、十几个套件级联 skip"，而 `curl` 手测一切正常。
规避：验证端口用 `127.0.0.1` 显式串，并在起服务前确认该端口未被 Docker 占用。
`db/rls-smoke.sh` 在容器内执行时需 `MSYS_NO_PATHCONV=1`，否则 `/tmp/db/...` 会被改写成 Windows 路径。

**陷阱记录二（会让人误判"API 不接受 cookie 鉴权"）**：`access_token` cookie 带 `Secure` 标志，
Python `urllib`/`http.cookiejar` 在 `http://` 下**不会回发**该 cookie → 手工探针一律 401，
容易被误读成"cookie 鉴权失效"或"中间件 CSRF 拦了写请求"。Chromium 把回环地址视为可信上下文，
照常发送 Secure cookie，所以浏览器路径与 UI 用例不受影响。手工探 API 请显式带
`Authorization: Bearer <token>`（token 从 `Set-Cookie` 里取），
或直接改用浏览器/Playwright 会话。
